2. 目标、范围与验收标准

  • 目标：把 Cockpit Tools 里点「登录」后手动填邮箱/密码/一次性验证码的流程，变成油猴脚本自动填（只填不提交）。
  • 原始需求（节选）：「就只要帮我填就行，其他我可以来操作，每次填之前先询问我使用哪个账号的账号密码」「能不能做成油猴插件」「把当前2FA框改为既可以填入2FA又可以填入辅助邮箱，自动识别并填入对应验证码」「现在可以要求每个账号都要把三个框填满，验证码都从最后一个框用对应方法获取。如果没有2fa就自动把第一个邮箱账号填入最后一个框」
  • 范围边界：做：Safari/Tampermonkey 油猴脚本 + 生成/安装/测试脚本。不做：Cockpit Tools 的任何改造（只读它的账号库）、不自动点提交、不接管客户端内嵌登录窗口。
  • 用户约束：不修改 Cockpit Tools 配置与数据；提交到 https://github.com/baiseraku/openai-auto-log-in 前必须给本机账号脱敏。
  • 验收标准：node scripts/test-userscript.mjs 退出码 0、断言全绿；node scripts/gen-userscript.mjs 生成的脚本 node --check 通过；release 产物无 __cockpitFill 调试后门。

7. 关键决策与原因

决策被放弃的备选原因
油猴脚本（Tampermonkey）自建 Chrome CDP 自动化、改 Cockpit 数据用户提出油猴；不碰 App 数据；AppleScript 权限被系统拒绝
面板由菜单命令打开页面自动弹面板用户要求点插件图标才出现
本地算 TOTP打开 2fa.fun / browserscan 查码不联网、不限流、不把密钥交给第三方
一次登录只确认一次每步确认（早期版本）用户要求减少打扰；确认框仍保留第一次
第三个框二合一分开的 2FA 框 + 辅助邮箱框用户要求合并；无 2FA 时自动填登录邮箱
测试用 fixture + 取码桩测试直接读真实账号库仓库是 PUBLIC，不能带真实账号；离线可复现
